# Owner-copy response-generation delay trial

The owner asked on October 22 to reduce the remaining thinking delay, then compare speed and accuracy in the separate test copy. Heart, its speaking speed and existing speech optimization remain fixed. Dad’s process, settings, Current design and care records stay unchanged. Only the existing owner Pro connection is used; no API billing, funding change or provider/account fallback is introduced.

## Method

First compare the current `gpt-6-sol/low` with `gpt-6-sol/none` on ten fixed synthetic cases, two repetitions each. Each candidate uses the current prepared context, Heart CPU12/72-character speech path and the exact immutable owner-practice account binding. Cases cover meal preferences/allergies, local appointment times, unavailable Outlook, empathy, medication boundaries, truthful activity reporting, task-text injection, repository preparation, unknown future schedules and allergy/nutrient uncertainty. Actual numeric usage and time to first provider text/final reply/validated audio are recorded; unknowns remain unknown.

[Official model documentation](https://developers.openai.com/api/docs/models/gpt-6-sol) lists both effort settings for Sol. [OpenAI’s reasoning guidance](https://developers.openai.com/api/docs/guides/reasoning) explains the latency/quality tradeoff; provider eligibility is established separately through actual completed requests on this existing connection. [Latency guidance](https://developers.openai.com/api/docs/guides/latency-optimization) supports shorter outputs and direct application logic for constrained source reads. No unsupported request fields or paid processing tiers are added.

The second comparison retains Sol/low and tests a default-off `quick-v1` read mode against the existing path. Six affected scenarios run twice per candidate. A single shared cap of 64 actual provider response requests covers both comparisons; no completed requests are replayed. The harness uses the real conversation/care/speech code, a restricted read-only connection after synthetic login, deterministic fictional facts and rotated sequential candidate order. Care writes and provider writes are blocked. Actual normal-service HTTP tests follow only after qualification.

## Bounded changes

The exact private owner/participant/origin selection may enable `read_mode: quick-v1` only alongside the existing prepared Sol/low and Heart speed trial. Main never reads it. The mode is included in conversation binding and metadata. Every normal authority/model/cancellation/reply check remains active, with no unvalidated speech release.

For simple read-only questions, a short answer contract limits unnecessary elaboration and asks for one repository meal option per requested slot. Necessary safety limits, unknowns and exact facts take precedence over length. Full planning, changes, approval/readback and ambiguous workflows keep their existing prompt and tool path.

Two narrowly bounded source reads avoid a model call. A plain B01 preparation question or immediate precise follow-up can read the recipe’s original two assembly steps, with its milk/gluten label caution. This is a source quote, not a personalized dietary recommendation or an accepted meal. Both public source hashes and the exact qualified recipe/wording must match; changed source, another recipe, scaling, substitutions, clinical suitability, extra intent or an unclear target falls through to the model. Exact ingredient quantities remain on the previously qualified fact path. The exact question about next week’s appointments may state the known today-only snapshot/unconnected-Outlook limit; it never infers an empty future calendar, creates an appointment or claims a connector read.

## Isolation and acceptance

The previous test selection/entry and source manifest are saved before activation. Rollback restores those private files and restarts only the verified owner-test child. There is no database migration, credential copy, global profile change, live restart or Current asset replacement.

Synthetic core-criteria review is not a clinical accuracy estimate or intended-person acceptance. Native timing ends when validated audio is available; microphone capture, remote Safari transport, audible onset and subjective listening remain separate gates. Initial and refined results are preserved separately, with their own source versions and small-sample/provider-load limits. No full slice is completed by this trial.

## Results and review deployment

[Sanitized evidence](evidence/THINKING-DELAY-2026-10-22.json) records separate phases and limits. The initial forty answers passed 20/20 scoped core criteria for each effort. Model-required reply median was 2.79 seconds for low and 2.86 for none; both reported zero reasoning tokens in all 32 calls. This does not prove low always reasons without tokens, but it gives no basis to switch this trial to none. The final selection retains Sol-low.

The refined comparison uses six affected cases, two repetitions and the same Heart settings. Core checks pass 12/12 per variant. Median final reply is 2.56→2.12 seconds; median first audio is 3.39→2.73, with 12→8 model requests per twelve answers. Individual first-audio medians:

| Case | Existing | Quick reads |
|---|---:|---:|
| meals | 3.83 s | 2.95 s |
| empathy | 3.07 s | 2.73 s |
| injection | 2.65 s | 3.32 s |
| cooking | 4.11 s | 1.32 s |
| missing_schedule | 3.25 s | 0.81 s |
| recipe_safety | 3.12 s | 3.16 s |

The source quote returns only the requested original preparation steps, without adding ingredient amounts or deciding dietary suitability. Model-based questions still show material variation: the injection answer is slower in this sample, and the allergy/nutrient answer is essentially unchanged. These small samples do not establish percentiles or clinical accuracy.

Actual authenticated test-service samples, one per case in each phase:

| Case | Before first audio | After first audio |
|---|---:|---:|
| recipe-1 | 3.30 s | 1.81 s |
| recipe_followup | 4.58 s | 1.40 s |
| meal | 3.32 s | 3.53 s |
| empathy | 2.55 s | 3.19 s |
| missing_schedule | 2.89 s | 0.82 s |
| recipe_safety | 3.70 s | 3.13 s |

These include model/provider and speech time; independently generated wording varies. Both normal HTTP phases validate every audio part, exact owner/test scope, no care save and numeric metadata. Cooking and the exact unknown next-week query use no inference after activation. They do not qualify Outlook retrieval: the practice connector is intentionally absent.

The running-service meal and empathy samples were slower after the change, so shorter prompts do not establish a reliable general model-speed improvement. The exact-quantity path is unchanged; its timing difference should not be credited to quick reads. Both actual empathy replies acknowledged the complaint without offering a useful continuation, leaving conversational helpfulness open despite the controlled core checks.

Final verification: 1047 full regressions pass with 2 optional skips across 113 files; 53 focused checks, typecheck, private build and final preservation/readiness pass. The Current assets and all 30 protected care tables are unchanged, both supervisors and Dad’s app/run are unchanged, and only the verified test child restarted. Benchmarks made 52 actual Pro response requests, with 8 further runtime model rounds observed under the shared 64-request reservation budget. No API billing, provider/care write, credential copy, paid service, speech change or live-client rollout occurred. Physical-device/listening/genuine-day and full-slice gates stay open.
