# October 19 client interface iteration

The owner requested a calmer interface for the intended client before the next review. The client has exactly five tabs: Tasks, Meals, Groceries, Progress and Ask for Help. Nancy branding returns to the homepage. Talk to Nancy stays available across views; opening another view does not restart an active conversation.

Suggestions for Nancy is at the top. Ways to use Nancy opens a short FAQ. The FAQ explains planning, actual reports, groceries, asking for help, reviewed Outlook actions, microphone behaviour and product feedback. Opening these pages does not start a microphone, infer consent or send a message. Ask for Help starts a focused Nancy conversation when its voice button is pressed; it does not automatically contact a support-team member.

Client views contain saved facts, without text inputs, dropdowns or manual care editors. Removed client surfaces include More, Activity, Day review, Routines, Sharing, Access settings, Outlook settings, Edit choices, Add appointment and the typed-conversation input. Caregiver-plan/usage text and foreground wake/off-state explanations are removed from the client homepage. Authentication and separately scoped staff setup remain outside this client simplification.

Your Day is a read-only timeline. It orders scheduled tasks, meals and local/selected Outlook appointments by participant-local time; untimed items are separate. Outlook rows retain source, cancellation and read freshness, with explicit partial/unavailable states. The timeline endpoint retrieves selected calendar events without reading Inbox messages. It does not turn appointments into care-task acceptance or attendance reports. The redundant See tasks/See meals links are removed.

The existing reviewed voice meal, grocery, planning, actual-report, preference and recovery commands remain server-authorized. Two gaps exposed by removing forms are repaired through the existing LocalDay command/recovery path: adding an ordinary client task choice, and adding a local appointment. A task choice does not accept a day plan or report completion; a local appointment does not send an Outlook invitation. Both require exact spoken review and confirmation and retain idempotent, actor-bound receipts. Clinical protocols and family-task acceptance boundaries are unchanged.

Product feedback is saved separately from care preferences, actual reports and significant-event notes. Nancy reads the exact suggestion back; only completed playback followed immediately by `save this suggestion` commits it. Interruption, an intervening topic, changed access or ambiguous approval cannot confirm it. The existing append-only command/event tables preserve actor, participant, key and receipt; uncertain saves reconcile by the same key. The client can read their own saved suggestions, and the participant's scoped administrator can review them in the staff interface. No outbound notification or public posting is performed.

The existing Outlook account, permissions, credentials and exact caregiver reasoning route are preserved. No schema migration, model change or API billing is needed. Long email content that cannot fit a complete voice review must be shortened before sending; removing settings screens never authorizes an unreviewed send.

Tests for explicitly removed client manual editors are replaced with five-tab/read-only, conversation continuity, calendar scope/failure, exact voice review, duplicate/revoked-scope and recovery tests. Existing server authorization, ledger, staff form and provider tests remain. Browser review can qualify this engineering iteration while the intended client is unavailable; it cannot establish intended-person/device, genuine-day or full-slice acceptance.
